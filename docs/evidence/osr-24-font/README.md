# OSR-24 TTF bounds evidence

Paths are normalized: `<evidence-root>` is the out-of-tree evidence directory and `<repo>` the working checkout.

## Fixture

`tests/corpus/truncated-cmap-184.ttf`, generated by `python3 tests/font_fixtures.py` (verify with `--check`).
184 bytes, SHA-256 `7aebf921202f4a86939c824ffa0be4a974c967b46b2b86cf9f680e81f0f78d3b`.
Layout: 76-byte directory, then head (54), hhea (36), hmtx (4) and a final 14-byte cmap: version 0, one (3,1) record with rel=12, and only the 2-byte format=4 field of the subtable. The format 4 length field would lie at bytes 184..185, past the file.

## Original failure (accepted base 075455c)

- `baseline-075455c-loader-{gcc,clang}.txt`: `load_font.c` compiled with the pristine `src/font.c` and `-fsanitize=address,undefined`. Both report a heap-buffer-overflow READ 0 bytes after the 184-byte region in `ru16` from `format4` (`font.c:132`). Exit status 1.
- `baseline-075455c-suite-{gcc,clang}.txt`: the new `font_bounds` test against the pristine `font.c`, through `make CC=... test-san`. GCC UBSan reports an insufficient-space load and Clang ASan a heap-buffer-overflow, both at `format4` `font.c:132` in the rel=len−2 case. Exit status 2.

The baseline loader read the format field after checking only `rel + 2 <= len` and then read the length field at `rel + 2`.

## Fix

`src/font.c` checks every span with `span_ok(len, off, need)` (`off <= len && need <= len - off`) before reading. That covers the directory header, table entries, the cmap header, encoding records, the subtable format and length (4 bytes), the subtable body, format 4 segment arrays, idRangeOffset glyph reads and hmtx entries. `hmtx` must hold `numberOfHMetrics` long metrics, and `numberOfHMetrics` must be nonzero. An encoding record whose 4-byte subtable header does not fit is skipped. A selected (3,1) format 4 subtable whose declared length is below 14 or past the cmap table rejects the font. The 8 MiB file cap is unchanged. Failures surface as `KI_CAUSE_FONT` (`XML2PDF_ERR_XML`, CLI exit 1).
