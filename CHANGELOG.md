# Changelog

Версии до 1.0 не обещают стабильный ABI. Совместимость ломается вместе с номером 0.y.

## Unreleased

- Write an optional PDF `/Info` dictionary with `Title`, `Producer` and an explicitly supplied `CreationDate`. The CLI adds `--title`, `--producer` and `--creation-date`, each accepted once; `KiConfig` gains `title`, `producer` and `creation_date` (`NULL` by default) after its geometry fields, and `ki_config_init` and the `_cfg` calls also accept the geometry-only size `KI_CONFIG_SIZE_GEOMETRY`. Title and producer are UTF-8 of 1–1024 bytes (`KI_INFO_TEXT_MAX`) without control characters other than tab, LF and CR, written whole as UTF-16BE hexadecimal text strings, so delimiters, backslashes, newlines and PDF syntax in a value cannot add keys or objects, and no body-font glyphs are needed. The date is `YYYY-MM-DDTHH:MM:SSZ` or `...±HH:MM` with a real calendar date and is written as `D:YYYYMMDDHHmmSSZ` or `D:...±HH'mm'`. A field that is not given is not written: there is no implicit date, `ModDate`, XMP stream, trailer `/ID` or PDF/A or PDF/UA claim, and without metadata the output is byte-identical to before. Invalid metadata is `KI_CAUSE_USAGE` (exit 2) before any file is opened or callback runs. The dictionary is one object after the catalog; its bytes count against output quotas and the xref ceiling, and page content, geometry and page count are unchanged. `KiOptions`/`KiResult`/`KiEvent` and exports are unchanged.
- Choose the page geometry: Letter or A4 in portrait or landscape, or a custom 3–14400 pt page, with 0–14400 pt margins and 1–144 pt type (leading 1.4 × size), rounded to 0.001 pt. The CLI adds `--page-size letter|a4`, `--orientation portrait|landscape`, `--page-width`/`--page-height`, `--margin PT|T,R,B,L` and `--font-size`, each accepted once as a plain decimal. The API adds `KiConfig`, `ki_config_init` and `ki_convert_file_cfg`/`ki_convert_cfg`/`ki_convert_to_file_cfg` in a new `KI_0_3` symbol version; `KiOptions`/`KiResult`/`KiEvent`, the 0.2 functions and their exports are unchanged, and a `NULL` config or the defaults give byte-identical Letter 612 × 792, 40 pt, 10/14 pt output. Layout and the PDF writer share one geometry for the MediaBox, line width, first baseline and lines per page. Placement now uses each glyph's outline box from `glyf`/`loca` (the advance box for fonts without outlines), so ink stays inside the margins: a line starting with a negative left side bearing moves right, and a glyph cluster wider than the line is `KI_CAUSE_RESOURCE`. Invalid geometry, a page with no room for one line and a font glyph wider than the line are `KI_CAUSE_USAGE` (exit 2) before any read, write or map callback; the CLI opens a file input only on the first read. A `glyf` without `loca` (or the reverse) or an outline outside its table is `KI_CAUSE_FONT`.
- Wrap text between words instead of at the first overflowing character. Space and tab are the only break opportunities; NBSP, hyphens and punctuation stay inside words, and no hyphen is inserted. A word that does not fit after the line's content moves to the next line whole; a word wider than a line, or longer than the 1023-byte line, is cut at a complete UTF-8 code point (before a code point with an advance, so marks stay with their base). Spaces after a word stay on its line and are not drawn past the right margin. The pending word shares the existing line buffer, so layout memory is unchanged for any token length. `ki_doc_break`, element ends and end of input place it once, and splitting text across calls, events or read sizes gives the same lines. Line and page breaks of existing documents can change. A run of zero-advance marks over 1023 bytes is now cut before its base when possible; one base with more than 1023 bytes of marks is still `KI_CAUSE_RESOURCE`. `KiOptions`/`KiResult`/`KiEvent` and exports are unchanged.
- End XML, built-in profile and `ki_doc_fail` messages with `at line L, column C, byte B` instead of `at byte N`: the consumed input position with a 1-based line, a 1-based Unicode-scalar column and a 0-based raw byte offset. A BOM adds bytes but no column, CR/LF/CRLF each end one line, references and CDATA count their source spelling, and malformed UTF-8 is reported at the consumed position where the parser next checks it: right after the invalid byte in text, CDATA, comments, PI data and DOCTYPE bodies, after the closing `>` in start/end tags (so `<r a='\x80abc'/>` is line 1, column 14, byte 13), before `<` or at EOF for a cut-off sequence. Positions are identical for every read size. `ki_doc_fail` now appends the position itself and shortens long rules at a UTF-8 boundary to keep the whole position in the 160-byte message; the catalog example no longer formats its own offset. A position counter that would wrap fails with `KI_CAUSE_RESOURCE`. Other causes and their messages are unchanged; `KiOptions`/`KiResult`/`KiEvent` and exports are unchanged.
- Compress page contents and the embedded TrueType font with zlib as `/FlateDecode` streams. Each compressed stream is deflated through a fixed 16 KiB window straight into the counted output; its `/Length` is an indirect object written after the stream, so callbacks and pipes still receive forward-only output and no compressed stream is held whole. The font stream keeps `/Length1` equal to the original font size. A page now uses three objects (contents, contents length, page). Every compressed byte counts against output quotas and the xref ceiling. A zlib allocation failure is `KI_CAUSE_RESOURCE`; any other compressor error is `KI_CAUSE_IO` "pdf compression failed", and file destinations are preserved. zlib is a new build and link dependency: Make links it into the CLI, shared library and examples, `pkg-config --static` adds `Libs.private: -lz`, the CMake package calls `find_dependency(ZLIB)` and static targets link `ZLIB::ZLIB`. The public header, `KiOptions`/`KiResult`/`KiEvent` and exports are unchanged.
- Count every emitted PDF byte in one checked place and cap the total at 9,999,999,999 bytes even when `max_output_bytes` is 0, so no classic xref offset or `startxref` needs an eleventh digit. Crossing the ceiling fails with `KI_CAUSE_RESOURCE` before the bytes reach the destination. For `ki_convert`, `output_bytes` is the number of bytes `write_bytes` actually accepted, including bytes flushed while the stream closes; buffered bytes a failing callback never accepted are not counted (a first-write rejection reports 0). An output quota equal to the PDF size succeeds and one byte less fails, including during xref/trailer finalization.
- Name the embedded font in `BaseFont`/`FontName` by its own PostScript name (name ID 6) instead of a fixed `DejaVuSans`, escaping PDF delimiters, whitespace and `#` as `#XX`. A font without a usable 1–63 character printable-ASCII name gets a deterministic `KiFont-XXXXXXXX` name from a hash of its bytes; a `name` table whose header or records lie outside the table, or a truncated `maxp`, is rejected with `KI_CAUSE_FONT`.
- Treat a glyph with zero advance as present: combining marks such as U+0301, U+0306 and U+0483 in DejaVu Sans now render with width 0 and extract through ToUnicode/ActualText, instead of failing as missing. A GID of 0 or at/past `maxp` numGlyphs is still a font error. Each GID maps back to a single code point. No shaping, composition or new repertoire.
- A line longer than 1023 UTF-8 bytes that cannot wrap (a long run of zero-advance marks) now fails with exit 4 and `KI_CAUSE_RESOURCE` instead of an XML error. Page streams are sized for 50 such full lines.

- Reject TTF files whose cmap subtable header, encoding records, table directory or table spans are truncated or out of range with `KI_CAUSE_FONT`, without reading past the font data. All range checks avoid offset-plus-length overflow. The `hmtx` table must hold all `numberOfHMetrics` entries. The 8 MiB font size cap is unchanged.
- Validate every consumed scalar as an XML `Char` and well-formed UTF-8 in text, attributes, CDATA, comments, PIs, the skipped DTD, skipped records and content after the root. A literal U+FFFE/U+FFFF is now `KI_CAUSE_XML` instead of a font error or success, and text events never end inside a UTF-8 sequence. Accept `xml-stylesheet` and other non-`xml` PI targets; reject empty or non-name PI targets and `&#X...;`. Require ordered, unique, space-separated XML declaration pseudo-attributes, a single DOCTYPE with white space after the keyword, and skip its internal subset with comment/PI/quote awareness. External DTDs and entities are still never loaded or expanded; parser limits are unchanged.

## 0.2.0

- Initialize `KiResult` before callback option validation, so reused results never retain earlier metrics on a usage error.
- Add CMake out-of-tree builds, CTest, installed `ki_xml_pdf::ki_xml_pdf`/static/shared targets and pkg-config discovery for Make and CMake installations.
- Accept `-` for CLI stdin/stdout, `-h` for help and `--` for paths beginning with a hyphen. Stream failures return a failure status; stdout may contain a partial PDF.
- Add `ki_convert_to_file` for callback input with the existing atomic file publication, quotas and cancellation contract. Preserve `KiOptions` layout and all existing exports.
- Provide a bounded public catalog mapper with English output, one-byte callback reads, independent text oracles and grammar diagnostics.
- Add English onboarding, contribution/security guidance and report-v1 documentation; retain Russian onboarding. Existing report-v1 labels and selection/whitespace rules are unchanged.
- Derive CLI/build/package/source archive versions from the public header, archive the exact Git HEAD and retain source commit/checksum provenance after the complete CI gates. A version tag or GitHub Release remains a separate action.

## 0.1.0

- Потоковый профиль records-v1, шрифт DejaVu, атомарная публикация PDF.
- Публичный вызов `ki_convert_file` с квотами, отменой и сменным mapping.
- Лицензия исходников — MIT (`LICENSE`). Профиль `report-v1`: `--profile report-v1`, выборка `--record-offset`/`--record-limit`. `KiOptions` инициализируется `ki_options_init`; несовпадение `size` — ошибка вызова.
- Символ вне репертуара шрифта — `KI_CAUSE_FONT` и `U+` код и в `records-v1`, и в `report-v1`. Ошибка профиля называет правило и смещение в байтах (`KiEvent.byte_offset`, включая конец самозакрывающегося элемента). Отмена во время `fsync` не публикует PDF. Смена `PREFIX` пересобирает путь шрифта.
- GitHub CI явно устанавливает Poppler/Python для sanitizer tests и сохраняет проверенный source archive с SHA-256 и commit. Добавлены инструкции установки и публичного API; измерения привязаны к публичной Git-ревизии.
