When to use / When not to use

When to use

  • You need a library or CLI on 64-bit Linux with glibc, using GCC or Clang and a GNU-compatible linker. README.md:13-25@ec84339
  • You can supply the project's report-v1 schema for sequential named fields, use records-v1 for diagnostic element/attribute/text output, or write a mapper for your schema. README.md:7@ec84339 docs/mapper-guide.md:3-6@ec84339
  • Your input is UTF-8 and your body text fits the documented DejaVu Sans repertoire, including Latin and Cyrillic. README.md:275-277@ec84339
  • You need file conversion or stdin/stdout pipelines, with atomic publication for a file destination. README.md:35-54@ec84339

When not to use

  • Other platforms: macOS, musl/Alpine, BSD and Windows are unsupported. README.md:13-22@ec84339
  • A full XML processor: this is a documented XML subset. External DTDs/entities are never loaded and internal entity declarations are not expanded. README.md:273-275@ec84339
  • UTF-16 input: only UTF-8 is supported. README.md:275@ec84339 README.md:316@ec84339
  • Namespaced report input: report-v1 rejects namespace prefixes and declarations except the predefined xml:space field attribute. docs/report-v1.md:29-31@ec84339
  • Tables, global sorting or XSL-FO: layout is sequential text blocks; these features are outside the contract. README.md:316@ec84339
  • Arbitrary scripts or text shaping: body text is limited to the documented font repertoire, without shaping, composition or normalization. Characters outside it fail instead of receiving a fallback glyph. README.md:277@ec84339
  • Archival or accessible PDF conformance: the project makes no PDF/A or PDF/UA claim. README.md:90@ec84339
  • Automatic conversion of an unknown XML schema: schemas other than the built-in profiles need an adapter. README.md:7@ec84339 docs/mapper-guide.md:3-6@ec84339
  • Rollback of streamed output: stdout and callback bytes already delivered cannot be recalled after a late error. Check success before using the PDF. README.md:47@ec84339

Usage

CLI: file and stdin/stdout

Continue in the consumer directory created above; it contains the repository's report-v1.xml fixture. - selects stdin or stdout. During conversion stdout contains PDF bytes and diagnostics go to stderr. README.md:35-45@ec84339

xml2pdf --profile report-v1 report-v1.xml report.pdf
cat report-v1.xml | xml2pdf --profile report-v1 - from-stdin.pdf
xml2pdf --profile report-v1 report-v1.xml - > from-file.pdf
cat report-v1.xml | xml2pdf --profile report-v1 - - > pipeline.pdf

Check the converter exit status. A successful file conversion publishes the complete PDF atomically; a late error on stdout can leave a partial PDF. README.md:47@ec84339

C API

The complete report.c example copied during Install is shown below unchanged. It initializes options, selects the report profile and reports conversion errors. examples/report.c:1-22@ec84339

#include "ki_xml_pdf.h"

#include <stdio.h>

/* xml2pdf --profile report-v1 is the CLI. This file is the same choice through the API. */

int main(int argc, char **argv) {
    const char *in = argc > 1 ? argv[1] : "examples/report-v1.xml";
    const char *out = argc > 2 ? argv[2] : "report.pdf";
    KiOptions opt;
    ki_options_init(&opt);
    opt.profile = KI_PROFILE_REPORT;
    KiResult result;
    int rc = ki_convert_file(in, out, &opt, &result);
    if (rc != 0) {
        fprintf(stderr, "report: %s\n", result.message);
        return rc;
    }
    printf("pages=%d total=%llu selected=%llu skipped=%llu\n", result.pages, result.report_total,
           result.report_selected, result.report_skipped);
    return 0;
}

Custom XML schema

Start with the mapper guide. The working catalog adapter demonstrates a project-owned schema through the public API without changing the parser, layout or PDF writer. It is an example to adapt, not automatic support for unknown schemas. docs/mapper-guide.md:3-6@ec84339

Mapper events are borrowed for the duration of the callback. Keep bounded mapper state, emit text through ki_doc_text / ki_doc_break, and report schema failures with ki_doc_fail. README.md:245@ec84339 Custom mappers wiki

Comparison guidance

Use the documented limits to decide whether to evaluate another tool:

  • For tables, global sorting or an XSL-FO workflow, look for a converter whose documented contract covers those requirements; they are outside ki_xml_pdf's scope. README.md:316@ec84339
  • For a platform other than Linux/glibc, seek a library that explicitly supports your deployment target. README.md:13-22@ec84339
  • For PDF/A or PDF/UA conformance, choose a workflow with an explicit conformance claim and validation; ki_xml_pdf makes neither claim. README.md:90@ec84339
  • For body text beyond the documented repertoire or for shaping, evaluate a text engine that documents those needs. README.md:277@ec84339
  • For an existing XML vocabulary, budget for a mapper here or evaluate a converter that explicitly documents that vocabulary. docs/mapper-guide.md:3-6@ec84339

These are selection criteria, not claims about any named competing library. The repository reports no measured adoption or comparisons with other converters. README.md:316@ec84339
