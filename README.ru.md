# ki_xml_pdf

[English README](README.md)

Библиотека на C и CLI для преобразования больших XML в PDF с ограниченной памятью, версия 0.3.0. В 0.3.0 добавлены геометрия страницы (Letter/A4, книжная/альбомная или свой размер, поля и кегль), перенос по словам, сжатие страниц и шрифта Flate, необязательные сведения PDF `/Info` и позиция ошибки в виде строки, столбца и байта. Новые вызовы только добавлены: программы, собранные с 0.2.0, работают с разделяемой библиотекой 0.3.0. Профиль [report-v1](docs/report-v1.md) выводит последовательный отчёт с полями и явной выборкой записей. Другие XML-схемы подключаются через callback mapping; [руководство адаптера](docs/mapper-guide.md) показывает собственный пример каталога. Диагностический `records-v1` печатает имена элементов, атрибуты и текст; он используется по умолчанию.

Исходники и собственные примеры распространяются по [MIT](LICENSE). Шрифт DejaVu имеет [отдельное уведомление](fonts/DejaVuSans.copyright). Репозиторий: [artemklen/ki_xml_pdf](https://github.com/artemklen/ki_xml_pdf); результаты проверок: [GitHub Actions](https://github.com/artemklen/ki_xml_pdf/actions/workflows/ci.yml).

Исторический замер на ревизии `7c62fe4`: на собственной синтетике около 1 ГиБ с выборкой первых 1000 записей RSS конвертера составила 2372 КиБ, PDF — 41 страницу / 1 009 241 байт. Без выборки сохраняются все записи; размер PDF и время зависят от содержимого. Ревизия, команды, бюджеты и границы этих измерений описаны в [контрактах](docs/contract.md). Текущий baseline на `075455c` — в разделе [«Ресурсный baseline 075455c»](#ресурсный-baseline-075455c).

## Сборка и запуск

Поддерживаемый стенд: Linux 64-bit с glibc, GCC или Clang, GNU Make и заголовки zlib (Debian/Ubuntu: `zlib1g-dev`). Сборка использует GNU/POSIX API и GNU-compatible linker. Работа на других ОС не проверена.

```sh
make
./xml2pdf --profile report-v1 examples/report-v1.xml report.pdf
```

Выборка большого входа и ограничения результата:

```sh
./xml2pdf --profile report-v1 --record-offset 0 --record-limit 1000 \
  --max-pages 10000 --max-output-bytes 268435456 \
  --max-spool-bytes 67108864 input.xml report.pdf
```

Даже при выборке весь XML дочитывается и валидируется. Без `--record-limit` данные не пропускаются. Файловый API сохраняет прежний PDF при ошибке.

Начиная с версии 0.2.0 `-` задаёт stdin или stdout. Например:

```sh
cat examples/report-v1.xml | ./xml2pdf --profile report-v1 - report.pdf
./xml2pdf --profile report-v1 examples/report-v1.xml - > report-stdout.pdf
```

Сообщения конвертации идут в stderr. При поздней ошибке stdout может содержать неполный PDF: проверяйте код завершения. `-h` и `--help` возвращают 0; `--` завершает разбор параметров для путей с дефисом. [Английское руководство](README.md) содержит полный набор pipeline-примеров и инструкции CMake/pkg-config для установленной библиотеки.

### Геометрия страницы

По умолчанию страница Letter книжная (612 × 792 пт), поля 40 пт, кегль 10 пт, интерлиньяж 14 пт. Все размеры — в пунктах PostScript (1/72 дюйма):

```sh
./xml2pdf --page-size a4 --orientation landscape input.xml a4-landscape.pdf
./xml2pdf --page-width 360 --page-height 504 --margin 24 --font-size 12 input.xml custom.pdf
./xml2pdf --margin 36,40,48,40 input.xml margins.pdf
```

- `--page-size letter|a4`: Letter 612 × 792 или A4 595,276 × 841,89 (210 × 297 мм). `--orientation landscape` меняет местами ширину и высоту, по умолчанию `portrait`.
- `--page-width PT --page-height PT`: свой размер, 3–14400 пт по каждой стороне. Задаются только вместе и не сочетаются с `--page-size` и `--orientation`.
- `--margin PT` задаёт все четыре поля, `--margin T,R,B,L` — верхнее, правое, нижнее и левое. Каждое 0–14400 пт; между полями должны остаться положительные ширина и высота.
- `--font-size PT`: 1–144 пт. Интерлиньяж — 1,4 кегля.
- Значения — простые десятичные числа вроде `24` или `10.5` (без знака, экспоненты и единиц), округляются до 0,001 пт. Каждый параметр указывается не больше одного раза.

MediaBox в PDF и размещение текста используют одни и те же округлённые значения. В поля попадают контуры глифов, а не только ширины: строка, первый глиф которой выходит левее начала, сдвигается вправо, а первая базовая линия и число строк на странице (не больше 50) оставляют место для самого высокого и самого глубокого глифа шрифта. Неверная геометрия завершает работу с кодом 2 до чтения входа и до создания или изменения выходного файла. Так же завершается допустимая страница, на которой не помещается ни одна строка или какой-либо отдельный глиф шрифта; это проверяется сразу после загрузки шрифта.

### Сведения о документе

Словарь `/Info` записывается только по запросу. Три необязательных поля заполняют обычный `/Info`; не заданное поле не записывается, дата никогда не берётся из системных часов:

```sh
./xml2pdf --title "Отчёт за октябрь" --producer "billing export" \
  --creation-date 2026-10-16T12:34:56+03:00 input.xml titled.pdf
```

- `--title TEXT` и `--producer TEXT`: UTF-8, 1–1024 байта. Допустим любой символ Unicode, кроме управляющих (табуляция, LF и CR разрешены); некорректный UTF-8 отклоняется. Значение сохраняется целиком как текстовая строка PDF в UTF-16BE (hex), поэтому скобки, обратная косая черта, переводы строк и синтаксис PDF остаются текстом. Глифы в шрифте тела для них не нужны.
- `--creation-date DATE`: строго `YYYY-MM-DDTHH:MM:SSZ` или `YYYY-MM-DDTHH:MM:SS+HH:MM` (`-HH:MM`). Дата должна существовать в григорианском календаре, секунды 00–59, смещение не больше 23:59. Записывается как задано, например `D:20261016123456+03'00'`.
- Каждый параметр указывается не больше одного раза. Неверные сведения завершают работу с кодом 2 до чтения входа и до создания или изменения выходного файла, даже если вход или шрифт не существуют.

Словарь не меняет содержимое страниц, геометрию и число страниц, его байты учитываются в `--max-output-bytes`. Это обычный `/Info`: без `ModDate`, XMP, `/ID` в trailer и без заявлений о PDF/A или PDF/UA.

## Установка и API

```sh
make install PREFIX="$HOME/.local"
cc -I"$HOME/.local/include" examples/report.c \
  "$HOME/.local/lib/libki_xml_pdf.a" -lz -o report-example
./report-example examples/report-v1.xml report.pdf
```

Статическая библиотека требует `-lz` (`pkg-config --static` добавляет его сам, CMake-пакет вызывает `find_dependency(ZLIB)`). Для shared library линковка использует `-L<prefix>/lib -lki_xml_pdf`; зависимость от zlib записана в самой `.so`, каталог должен быть доступен runtime linker. Содержимое страниц и встроенный TrueType-шрифт записываются потоками `/FlateDecode`; `/Length` каждого сжатого потока лежит в следующем за ним косвенном объекте, поэтому writer не делает seek и не держит сжатый поток целиком. У шрифта `/Length1` равна исходному размеру файла; ToUnicode CMap не сжимается. Устанавливаются публичный заголовок, `.a`, `.so`, font и notices. `PREFIX` задаёт runtime-путь шрифта; `DESTDIR` только стадирует файлы. При переносе данных можно явно задать `KiOptions.font_path` или `KI_XML_PDF_FONT`.

```c
#include "ki_xml_pdf.h"
#include <stdio.h>

int main(void) {
    KiOptions options;
    ki_options_init(&options);
    options.profile = KI_PROFILE_REPORT;
    options.record_limit = 1000;
    options.max_pages = 10000;

    KiResult result;
    int status = ki_convert_file("input.xml", "report.pdf", &options, &result);
    if (status != 0) {
        fprintf(stderr, "%d: %s\n", result.cause, result.message);
    }
    return status;
}
```

`ki_convert_to_file` читает через read callback и атомарно публикует файловый результат, игнорируя write callback. Ресурсы callbacks остаются во владении вызывающего кода. `ki_convert` принимает read/write callbacks; короткое положительное чтение не означает EOF. Уже принятые output callback байты не откатываются при ошибке. Независимые conversion calls могут работать одновременно; библиотека не меняет signal handlers приложения. Примеры: [C](examples/report.c), [C++](examples/consume.cpp); полный публичный контракт — [ki_xml_pdf.h](include/ki_xml_pdf.h).

Геометрия страницы задаётся отдельной структурой `KiConfig`, поэтому раскладка `KiOptions`, `KiResult` и `KiEvent` и экспорты 0.2 не меняются. `ki_config_init(&cfg, sizeof cfg)` записывает значения по умолчанию: Letter, книжная ориентация, поля 40 пт, кегль 10 пт. Затем можно задать `page_size` (`KI_PAGE_LETTER`, `KI_PAGE_A4`, `KI_PAGE_CUSTOM`), `orientation` (`KI_ORIENT_PORTRAIT`, `KI_ORIENT_LANDSCAPE`), `page_width`/`page_height` (только для своего размера), `margin_top`/`margin_right`/`margin_bottom`/`margin_left` и `font_size` и вызвать `ki_convert_file_cfg`, `ki_convert_cfg` или `ki_convert_to_file_cfg`; `NULL` вместо `KiConfig` даёт геометрию по умолчанию без `/Info`. Поля `title`, `producer` и `creation_date` (`const char *`, по умолчанию `NULL` и тогда не записываются) задают `/Info` по правилам раздела «Сведения о документе»; `KI_INFO_TEXT_MAX` — предел 1024 байта. Библиотека копирует их в начале вызова. Неверный `size` (допустимы `sizeof(KiConfig)` и `KI_CONFIG_SIZE_GEOMETRY` — конфигурация только с геометрией, без полей `/Info`) или значение — `KI_CAUSE_USAGE` (`page geometry: ...` или `metadata: ...`) до открытия файлов и вызова callbacks.

## Проверки

Для проверок нужны compiler, `python3`, `/usr/bin/time`, `pdfinfo` и `pdftotext` (Poppler). Примеры и install checks также используют C++ compiler. В Ubuntu/Debian: `gcc g++ clang make zlib1g-dev python3 time poppler-utils`. Эти зависимости нужны и sanitizer jobs. Если reader отсутствует, проверка завершается ошибкой.

```sh
make check
```

`make check` удаляет прежние `xml2pdf` и `test_stream`, заново собирает их из исходников, прогоняет группы `tests/test_stream` и `tests/verify.sh`. Готовые бинарники для этого не нужны. `python3 tests/wrap_check.py` сверяет строки, страницы и рамки слов из Poppler с правилами переноса по ширинам, независимо прочитанным из шрифта поставки. `python3 tests/geometry_check.py` сверяет MediaBox каждой страницы (`pdfinfo`) и отрисованные контуры (`pdftoppm`) с заданными размером и полями и проверяет, что неверная геометрия даёт код 2, не читая stdin и не трогая файл назначения. `python3 tests/info_check.py` разбирает объект `/Info` через xref, декодирует строки, сверяет их и исходную дату с `pdfinfo`, проверяет, что тело, число страниц и текст совпадают с запуском без сведений, а неверные сведения дают код 2, не читая stdin и не трогая файл назначения. `python3 tests/integration_check.py` совмещает геометрию, перенос, отдельный шрифт со знаками нулевой ширины, Flate и `/Info` в обоих профилях, прогоняет каждый случай по всем четырём путям file/stdin → file/stdout, требует одинаковых байтов на каждом пути и сверяет слова, MediaBox, контуры, потоки и сведения с ожиданиями, вычисленными из входа; совмещённые поздняя ошибка XML и квота не меняют и не создают файл назначения.

Отдельно:

```sh
make clean
make test
./tests/verify.sh
make test-san
make distcheck
python3 tests/large_proof.py --self-test
python3 tests/large_proof.py 1073741824
```

## Ресурсный baseline 075455c

[Baseline OSR-23](docs/evidence/osr-23-baseline-075455c/README.md) снят на неизменённых исходниках 0.2.0 ревизии `075455c`, на одном Linux-стенде со шрифтом DejaVu Sans из поставки. Серий две, и они не подменяют друг друга:

- **Полный вывод**, все записи в PDF: `records-v1` и `report-v1` на 1, 16 и 64 МиБ. Пиковая RSS конвертера — 2340–2524 КиБ. Вход 64 МиБ дал 115 552 страницы / 713 436 448 байт (`records-v1`) и 39 033 страницы / 347 124 499 байт (`report-v1`).
- **Выборка** `report-v1 --record-limit 1000` из входов 16, 256 и 1024 МиБ: весь XML читается и валидируется, в PDF попадают 1000 записей. Пиковая RSS конвертера — 2340–2536 КиБ, каждый раз 41 страница и около 1,1 МБ PDF.

Независимый потоковый oracle сверил каждую выведенную запись с рецептом fixture. Там же лежат сырые CSV/JSON, отдельные замеры `/usr/bin/time` генератора, конвертера и reader, хеши и отрицательные контроли. Размер PDF, файла смещений и время растут вместе с выводимым содержимым; RSS включает загруженный шрифт и зависит от него. Полный вывод для входа 1 ГиБ не измерялся. Строки выборки не описывают полный вывод; сравнения с другими конвертерами нет.

Запуск конвертера:

```sh
./xml2pdf input.xml output.pdf
```

## Пределы парсера

Состояние парсера не растёт вместе с документом. Вход читается окном 4096 байт. Одновременно открыто не больше 64 элементов. Имя — до 63 байт, атрибутов не больше 8, значение атрибута — до 255 байт. Текст отдаётся кусками до 1023 байт.

Разбираются разметка, комментарии, инструкции обработки, объявление XML, один DOCTYPE и секции CDATA внутри элемента, пять предопределённых сущностей и числовые ссылки `&#...;` / `&#x...;` (строчная `x`). Внешние DTD и сущности не загружаются, сущности из внутреннего подмножества не раскрываются. Неизвестная сущность, CDATA вне элемента, `<!FOO>`, `]]>` в тексте, неверное объявление, управляющий байт, NUL и битый UTF-8 отклоняются. Буквальные CR/CRLF становятся LF.

Каждый прочитанный байт должен быть корректным UTF-8 и кодировать XML `Char`, в том числе в комментариях, инструкциях обработки, пропускаемой DTD, записях вне выборки и после корня: буквальный U+FFFE или U+FFFF — ошибка XML, а не шрифта. Объявление XML допустимо только в начале (после необязательного BOM UTF-8); псевдоатрибуты `version="1.0"`, необязательные `encoding="UTF-8"` и `standalone` идут в этом порядке, по одному разу и через пробел. Цель инструкции обработки — имя до 63 байт, за ним пробел или `?>`; цель `xml` в любом регистре зарезервирована, а `xml-stylesheet` и подобные — обычные инструкции, которые не выводятся. DOCTYPE стоит до корня; его внутреннее подмножество пропускается с учётом комментариев, инструкций и кавычек, поэтому `]` или `>` внутри них его не завершают. Пробел между словами сохраняется; отступ с переводом строки на пустой строке — нет, если нет `xml:space="preserve"` и это не CDATA. Это по-прежнему не весь XML 1.0.

### Позиция ошибки

Ошибка XML, ошибка встроенного профиля и любое сообщение `ki_doc_fail` заканчиваются на `at line L, column C, byte B` — позицию уже прочитанного парсером входа:

- Строка и столбец считаются с 1. Смещение считается с 0 в исходных байтах; BOM UTF-8 добавляет 3 байта и не добавляет столбца.
- CR, LF и CRLF завершают одну строку. Табуляция — один столбец. Столбец считает скалярные значения Unicode; ссылки и CDATA считаются по исходной записи, поэтому `&amp;` — пять столбцов.
- Байт, на который парсер только заглянул, не прочитан: неизвестная сущность указывается до её `&`, отсутствующий `>` — после последнего принятого байта. В конце входа позиция стоит после последнего байта.
- Битый UTF-8 (байт, который не может начать или продолжить последовательность, избыточно длинная запись, суррогат, значение выше U+10FFFF или скалярное значение, не являющееся XML `Char`) отмечается, когда прочитан байт, делающий последовательность неверной. Ошибка не обязательно указывается сразу после этого байта: указывается позиция, прочитанная парсером к моменту следующей проверки отметки, а парсер проверяет её после единицы, которую читает целиком (байт или символ, вся ссылка, весь тег). Где проходит проверка, зависит от контекста:
  - В тексте, CDATA, комментариях, данных инструкций обработки, литералах DOCTYPE и объявлениях разметки парсер проверяет после каждого прочитанного байта, поэтому ошибка указывается сразу после этого байта. `<r>a\x80b</r>` даёт line 1, column 6, byte 5.
  - В тексте ссылка на сущность или символ читается целиком и проверяется после её `;`. Если последовательность делает неверной `&` ссылки, например когда за неполной последовательностью идёт ссылка, ошибка указывается после ссылки: `<r>\xC3&amp;</r>` и `<r>\xC3&#38;</r>` оба дают line 1, column 10, byte 9. Если неизвестна или неверна сама ссылка, сообщается её ошибка: `<r>\xC3&bogus;</r>` — `unknown entity` в line 1, column 5, byte 4, а `<r>\xC3&#0;</r>` — `bad character reference` в line 1, column 9, byte 8.
  - В открывающих и закрывающих тегах (имена элементов, имена и значения атрибутов) — после закрывающего `>` тега. `<r a='\x80abc'/>` даёт line 1, column 14, byte 13.
  - В цели инструкции обработки — после цели. В значении объявления XML — после закрывающей кавычки. В имени DOCTYPE — на следующем проверяемом байте DOCTYPE, не позже его закрывающего `>`.
  - Последовательность, оборванная символом `<` в тексте, указывается до `<`. Последовательность, оборванная концом входа, указывается в конце входа.
  - Если в той же конструкции раньше найдена другая синтаксическая ошибка, например нет `=` или ключевое слово объявления не совпало, сообщается она, со своим текстом и позицией. Причина остаётся `KI_CAUSE_XML`.

  Байт продолжения внутри открытой последовательности не добавляет столбца; любой другой байт, в том числе неверный, добавляет один.
- Ошибки профиля и mapper указывают позицию после текущего события. Синтетический END пустого элемента имеет ту же позицию, что и его START.

Позиция не зависит от размера чтения и границ буфера и считается по ходу чтения, без хранения и повторного чтения входа. Если счётчик переполнился бы, преобразование останавливается с `KI_CAUSE_RESOURCE` (`resource limit: input position`). Сообщение укладывается в 160 байт `KiResult.message`; длинное правило укорачивается по границе символа UTF-8, а позиция остаётся целиком. Сообщения ввода-вывода, шрифта, ресурса, отмены и вызова не меняются и позиции не содержат. В `KiEvent` по-прежнему только `byte_offset`; публичные структуры не изменены.

## Подтверждённые ограничения

Смещения объектов PDF пишутся во временный файл, а не в растущий массив. На синтетике около 16 МиБ (десятки тысяч страниц) RSS конвертера остаётся около 2–3 МиБ: в неё входит шрифт, а не список страниц. Это не обещание, что любой вход уложится в ту же цифру. Потолок контракта — 64 МиБ RSS на стенде обзора.

Текст набирается DejaVu Sans (файл `fonts/DejaVuSans.ttf`, лицензия рядом). Кириллица, ё/Ё и тире U+2014 читаются `pdftotext`. Символ вне репертуара контракта — ошибка, а не пропуск. Символ есть в шрифте, если cmap ведёт к существующему глифу (GID не 0 и меньше numGlyphs из `maxp`), даже с нулевой шириной: комбинируемые знаки вроде U+0301 и U+0306 рисуются над предыдущим глифом и сохраняются при извлечении текста, без shaping, композиции и нормализации. Строка вывода — не больше 1023 байт UTF-8; одна базовая буква со знаками нулевой ширины длиннее этого разделиться не может и даёт ошибку ресурса (код 4, `KI_CAUSE_RESOURCE`). `BaseFont`/`FontName` в PDF — собственное PostScript-имя встроенного шрифта (name ID 6), экранированное как PDF name; шрифт без пригодного имени (печатный ASCII, 1–63 символа) получает `KiFont-XXXXXXXX` по хешу байтов файла, а шрифт с записями `name` за пределами таблицы отклоняется как ошибка шрифта. Строка переносится по ширине глифа внутри полей (по умолчанию 40 пт, см. «Геометрия страницы»), а не по 90 байтам.

### Перенос строк

Строки переносятся между словами по ширинам глифов самого шрифта:

- В строку помещается ширина между полями, по умолчанию 532 пт. Ширины до последнего непробельного глифа должны уложиться в `ширина × unitsPerEm / кегль` единиц шрифта с округлением вниз (`532 × unitsPerEm / 10` по умолчанию), а контур каждого глифа — закончиться внутри правого поля. Слово, которое заканчивается ровно на этой ширине, помещается, поэтому перед первым словом не бывает пустой строки.
- Место переноса — только пробел (U+0020) и табуляция (U+0009, ширина пробела). LF завершает строку, в том числе пустую. Неразрывный пробел (U+00A0), дефисы и знаки препинания входят в слово; дефис не добавляется, а NBSP остаётся U+00A0 в PDF.
- Слово, которое не помещается после уже набранного, начинает следующую строку. Пробелы и табуляции остаются в конце строки, за которой идут, даже за правым полем; за полем они не рисуются, но остаются в извлекаемом тексте.
- Слово шире целой строки начинается с новой строки и режется перед символом, который бы её переполнил. Слово длиннее 1023 байт строки режется так же, перед символом с ненулевой шириной, поэтому знаки нулевой ширины остаются со своей базой. Разрез всегда проходит по границе целого символа UTF-8, ничего не теряется.
- Незавершённое слово хранится в том же буфере строки на 1024 байта, поэтому слово любой длины (проверено на 64 КиБ и 4 МиБ) не требует дополнительной памяти. Это свойство буфера, а не предел длины слова.
- `ki_doc_break`, конец элемента во встроенных профилях и конец входа выводят незавершённое слово один раз. Перенос на пустой строке ничего не добавляет, поэтому несколько переносов подряд не дают пустых строк. Разбиение текста на несколько вызовов `ki_doc_text`, событий TEXT/CDATA или размеров чтения, в том числе внутри последовательности UTF-8, даёт те же строки.

Раньше текст переносился на первом не поместившемся символе, поэтому у того же документа теперь могут быть другие переносы строк и страниц.

Результат пишется во временный файл в том же каталоге и заменяет путь назначения через `rename` только после успешного разбора, сборки PDF, `fflush` и `fsync`. Один и тот же inode — тот же путь, жёсткая ссылка или символическая ссылка на исходник — отклоняется до изменения файлов. Символическая ссылка на другой файл при успехе заменяется новым файлом, а не записью сквозь ссылку. При ошибке прежний файл назначения не меняется, временный файл удаляется. После `SIGKILL` незавершённый временный файл может остаться рядом, но это не путь назначения.

Контракт ограничивает RAM конвертера на заявленном стенде. Вёрстка — последовательные текстовые блоки; таблицы, глобальные сортировки и XSL-FO не поддерживаются. Неизвестный XML требует отдельного адаптера. Параметры, typed errors, XML/font limits и quotas описаны в [контракте core](docs/contract.md) и [report-v1](docs/report-v1.md). Куда сообщать об ошибках, написано в [CONTRIBUTING.md](CONTRIBUTING.md).

## Исходный дистрибутив

`make distcheck` создаёт source archive из текущего Git HEAD, распаковывает и устанавливает его, запускает внешние C/C++ clients и проверяет report-v1 по oracle. `make dist` создаёт `ki_xml_pdf-0.3.0.tar.gz` и печатает SHA-256.

После успешных GCC, Clang, sanitizer и resource jobs [CI](https://github.com/artemklen/ki_xml_pdf/actions/workflows/ci.yml) сохраняет тот же source archive, `SHA256SUMS` и `SOURCE_COMMIT` как artifact. Для его загрузки требуется GitHub login. Формальный GitHub Release и version tag создаются отдельно от проверки исходников. [Чеклист приёмки](docs/release-checklist.md).
